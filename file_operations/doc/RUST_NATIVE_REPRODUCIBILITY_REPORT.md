# Rust Native Library Reproducibility Report

## Scope

This report investigates the native-library mismatch reported in
[issue #4551](https://github.com/TeamAmaze/AmazeFileManager/issues/4551#issuecomment-6204962568)
when F-Droid rebuilt version 3.11.4 with:

```shell
./gradlew assembleFdroidRelease
```

The APK difference was limited to `librootoperations.so` for every supported
ABI. The F-Droid-built libraries were substantially larger than the published
libraries:

| ABI | Published APK | F-Droid build |
| --- | ---: | ---: |
| `arm64-v8a` | 407,320 bytes | 661,160 bytes |
| `armeabi-v7a` | 253,564 bytes | 395,536 bytes |
| `x86` | 438,988 bytes | 591,260 bytes |
| `x86_64` | 440,336 bytes | 615,256 bytes |

## Investigation

The release APK published for v3.11.4 contains stripped native libraries:

- The ELF files do not contain `.symtab` or debug sections.
- They retain `.dynsym` and `.comment`, as expected for runtime loading and
  normal release metadata.

The Rust Gradle plugin builds `librootoperations.so` into two locations:

1. Cargo's normal target output:
   `file_operations/target/<target>/release/librootoperations.so`
2. The plugin's JNI staging directory:
   `file_operations/build/rustJniLibs/android/<abi>/librootoperations.so`

The latter is the input consumed by Gradle's JNI merge and, ultimately, APK
packaging.

Prior to the fix, a local `assembleFdroidRelease` build packaged the staging
copies without stripping them. The resulting library sizes matched the pattern
reported by F-Droid.

Android Gradle Plugin (AGP) creates native symbol-strip tasks such as:

```text
:file_operations:stripReleaseDebugSymbols
:app:stripFdroidReleaseDebugSymbols
:app:stripPlayReleaseDebugSymbols
```

However, the Rust plugin's staged JNI files could bypass the effective output
of that pipeline. In particular, the `ndk.debugSymbolLevel = 'FULL'` setting
in `file_operations/build.gradle` does not control Cargo-produced libraries;
it applies to Android NDK external-native builds.

AGP's actual release stripping command is:

```shell
llvm-strip --strip-unneeded <library>
```

`--strip-debug` is insufficient because it leaves the ELF `.symtab` section.
`--strip-unneeded` removes it and produces the same section layout as the
published release libraries.

## Fix

`file_operations/build.gradle` now registers
`stripRustReleaseDebugSymbols`, which:

1. Depends on `cargoBuild`.
2. Locates `llvm-strip` from the NDK version resolved by Gradle.
3. Runs `llvm-strip --strip-unneeded` on both the Cargo target outputs and
   the Rust Gradle plugin's JNI staging copies.
4. Runs before every release JNI merge task.

The task applies only when the build type is `release`. Debug builds preserve
their existing behavior.

Because the Rust library module is shared by both application flavors, this
fix applies equally to:

```shell
./gradlew assembleFdroidRelease
./gradlew assemblePlayRelease
```

There is no Play-only implicit stripping behavior. Both variants have the
same native-library pipeline; the differences between the flavors are
application configuration and signing, not Rust compiler or linker flags.

## Validation

The following command completed successfully:

```shell
./gradlew :file_operations:mergeReleaseJniLibFolders --rerun-tasks
```

The merged Rust JNI libraries were:

| ABI | Size after fix |
| --- | ---: |
| `arm64-v8a` | 407,352 bytes |
| `armeabi-v7a` | 253,596 bytes |
| `x86` | 439,020 bytes |
| `x86_64` | 440,368 bytes |

These sizes closely match the published v3.11.4 release. The small differences
are expected when comparing a current checkout/toolchain output with the
published release; the relevant stripping state is identical:

```text
.dynsym   present
.comment  present
.symtab   absent
.debug_*  absent
```

A forced full F-Droid release build was also run. The new Rust strip and JNI
merge tasks completed, but the host terminated the Gradle process during later
Kotlin processing before APK packaging completed. The focused module task
above verifies the exact JNI files consumed by that package step.

## Rebuild Requirements

For reproducible release builds, builders should use the versions tracked by
the repository:

- Rust: `file_operations/rust-toolchain.toml`
- Android NDK: `gradle/libs.versions.toml`
- Gradle and Android Gradle Plugin: `gradle/libs.versions.toml` and the
  Gradle wrapper
- JDK: the release workflow specifies JDK 21

The Android linker configuration is generated by
`file_operations/setup_rust_android.sh`, which is already invoked by the
Gradle setup task. No hidden `local.properties` setting or additional Gradle
flag is required for native-library stripping after this fix.
